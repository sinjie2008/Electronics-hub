# Public Product API v1

## Purpose and compatibility

This API exposes read-only product catalog data for public product pages and server-side WordPress integrations. The existing Product Catalog Manager MySQL database remains the source of truth; the API adds no synchronization workflow, import, or schema migration. Its source contract is [Foundational-Electronics-Core-Systems commit c10faf4b5314668f7695a9c138a8e9333bee469d](https://github.com/sinjie2008/Foundational-Electronics-Core-Systems/commit/c10faf4b5314668f7695a9c138a8e9333bee469d).

All routes are under `/api/v1/catalog`. The route family has ten GET endpoints. JSON property names and nesting follow the source contract unless called out below. The root endpoint lists these versioned paths. The API is anonymous by design; use it from server-side WordPress PHP so database/API credentials and private integration configuration never enter browser JavaScript. Production traffic must use HTTPS. CORS remains disabled.

## Response format

Every successful response is HTTP 200:

```json
{"success":true,"data":{},"correlationId":"..."}
```

Every JSON error uses the same property casing and includes the matching HTTP status:

```json
{"success":false,"errorCode":"INVALID_QUERY","message":"...","details":[],"correlationId":"..."}
```

`X-Correlation-ID` is accepted after sanitization or generated by the server, and is returned in both the response body and header. Responses carry `Cache-Control: no-store, private` and `X-Content-Type-Options: nosniff`.

Common errors are `API_UNAVAILABLE` (503; API or Catalog module disabled, or read account unavailable), `METHOD_NOT_ALLOWED` (405 with `Allow: GET`), `INVALID_PATH` / `INVALID_QUERY` (422), `NOT_FOUND`, `CATEGORY_NOT_FOUND`, or `SERIES_NOT_FOUND` (404), `RESOURCE_LIMIT` (503), `RATE_LIMITED` (429 with `Retry-After`), `INVALID_HIERARCHY` (500), and generic `INTERNAL_ERROR` (500). Internal errors do not expose SQL, exception text, credentials, or catalog values. Unknown paths return the API error envelope. Only GET is supported; HEAD and other methods receive 405.

## Endpoints

The example paths below use illustrative fixture names and IDs, not guaranteed production records.

| Endpoint | Parameters | `data` payload |
|---|---|---|
| `GET /api/v1/catalog` | None | Root descriptor: `name`, `sourceOfTruth`, `readOnly`, migration/import/sync flags, `endpointCount`, versioned `endpoints`, and the `tree`. |
| `GET /api/v1/catalog/health` | None | `{status:"ok",writeOperations:false}` after a database read check. The source endpoint's `database` property is intentionally omitted. |
| `GET /api/v1/catalog/tree` | None | Array of recursive category/series nodes. |
| `GET /api/v1/catalog/resolve/{path}` | `path`: full slash-separated catalog path. Example: `electronics/passives/resistors`. | `{resource,breadcrumb}`. `breadcrumb` runs from root through the resolved node. |
| `GET /api/v1/catalog/categories/{path}` | `path`: full category path. Example: `electronics/passives`. | `{resource,breadcrumb,children}`; children are direct child nodes. Series children include `partCount`. |
| `GET /api/v1/catalog/series/{path}` | `path`: full series path. Example: `electronics/passives/resistors`. | `{resource,breadcrumb,metadata,fields,partCount}`. |
| `GET /api/v1/catalog/series/{path}/fields` | `path`: full series path. | Bare array of public product-attribute field definitions. |
| `GET /api/v1/catalog/series/{path}/parts` | `path`, plus the query parameters below. | `{series,fields,parts,pagination}`. |
| `GET /api/v1/catalog/series/{path}/facets` | `path`: full series path. | `{series,totalParts,facets}`. File fields are present with an empty `values` list. |
| `GET /api/v1/catalog/search?q={keyword}` | `q`: optional search term, up to 100 characters. | `{query,nodes,parts}`. Empty `q` returns empty lists; part matches are capped at 100. |

A public node has `{id,parentId,name,type,slug,path,displayOrder}`. `type` is `category` or `series`; `parentId` is an integer or null. Tree nodes also have `children`; series tree nodes have `partCount`. Series resources add `metadata` entries `{key,label,type,value,sortOrder}` and field entries `{id,key,label,type,defaultValue,sortOrder,required}`. Part records are `{id,sku,name,description,values}` where `values` maps each public field key to its effective value.

### Parts query parameters

Only these query keys are accepted on `parts`; unknown keys or malformed shapes return 422 `INVALID_QUERY`.

| Parameter | Type and behavior |
|---|---|
| `search` | String, at most 100 characters. Case-insensitive literal substring search over part ID, SKU, name, description, and public non-file field values. SQL wildcard characters `%` and `_` are treated literally. |
| `filter[fieldKey]` | String, integer, null, or a list of those values (up to 20 values). Each field filter is exact and case-insensitive; multiple values for one field are ORed, while different fields are ANDed. At most 10 fields; field keys must be public, non-file product attributes. |
| `sort` | `id`, `sku`, `name`, or a public non-file field key. Default: `sku`. Text uses case-insensitive lexical ordering; `number` fields use numeric ordering. Ties use ID. |
| `direction` | `asc` or `desc`. Default: `asc`. |
| `page` | Positive integer. Default: `1`; a page beyond the last page is clamped to the last page. |
| `per_page` | Integer from 1 through 100. Default: `25`; larger or malformed values return 422. |

`pagination` is `{page,per_page,total,last_page}`. Facet buckets are exact stored values with counts, naturally sorted for display. Global search matches category and series names plus part SKU, name, and description; it does not search field keys or custom values. Node matches are not paginated.

## Postman testing

Import both [the Postman v2.1 collection](catalog-public-api-v1.postman_collection.json) and [its environment](catalog-public-api-v1.postman_environment.json). Select the `Electronics Hub — Public Product API v1` environment and set `base_url` to the application's origin, including its scheme and optional port, without `/api/v1/catalog` or a trailing slash. No login, bearer token, or database credentials are needed in Postman. The server must first meet the enablement and read-account requirements below; 503 `API_UNAVAILABLE` does not count as a successful test.

Run the collection once in its saved order with a 1,500 ms request delay. Its 16 GET requests cover all ten endpoints, parts search/sort/filter examples, and four expected validation/not-found errors. Assertions check status, response shapes, the common envelope, correlation ID, and security/cache headers.

With `auto_discover=true`, `Tree` fills empty category, series, resolve, and search variables from real data; `Parts` captures a sample SKU and `Facets` captures a public non-file filter with actual values. Existing paths are preserved. For manual testing, set `auto_discover=false` and supply raw slash-separated `resource.path` values. Clear discovered variables when switching server/catalog, and clear the part-search and filter variables when changing series. Scripts encode path segments and query values before sending.

Requests that require an unavailable category, series, or filter are skipped with an explanation in the Postman Console, using [Postman's pre-request skip API](https://learning.postman.com/docs/tests-and-scripts/write-scripts/postman-sandbox-reference/pm-execution/). Review skipped requests: an empty catalog cannot exercise all ten endpoints. Respect `Retry-After` if repeated runs reach the rate limit.

## Paths and slugs

Slugs lowercase names and replace runs of non-letter/non-number characters with `-`; an empty slug becomes `item`. A node path joins its ancestor slugs. When sibling slugs collide, numeric IDs are added until each sibling path is unique. For example, fixture IDs 12 and 13 with the same `Resistors` name might become `electronics/passives/resistors-12` and `electronics/passives/resistors-13`; the suffix IDs are illustrative only. Encoded path segments are decoded once. Malformed escapes, residual percent encoding, `..`, backslashes, double slashes, control characters, invalid UTF-8, and paths over the configured length are rejected with 422 `INVALID_PATH`. A syntactically valid but unknown path returns 404.

## Public visibility and media

A field is public only when both public hide flags are false: `is_public_portal_hidden` and `is_public_hidden`. If either flag is true, the field, its metadata, defaults, values, filters, sort options, search matches, and facet values are omitted. Backend hide flags (`is_backend_portal_hidden` and `is_backend_hidden`) control backend presentation; they do not grant or deny public API access.

The current field CRUD and UI read/write the `*_portal_hidden` columns through `publicPortalHidden` and `backendPortalHidden`. The older `*_hidden` columns remain in the imported schema and are not synchronized by those CRUD operations. This API conservatively treats either public hide flag as a denial. Clearing only the portal flag therefore does not publish a field whose older public-hidden flag is still set. No flag, existing administrator workflow, or stored value is changed by this integration.

File-type values are returned only when they are valid HTTPS URLs on an explicitly configured `CATALOG_PUBLIC_API_MEDIA_HOSTS` host. URLs with user info, ports, fragments, control characters, or traversal paths are rejected. Unapproved URLs and private relative storage paths return `null`, including file-field defaults and series metadata. File fields cannot be filtered, sorted, searched, or faceted. The API does not add a media serving route or expose the catalog's private storage paths; configure approved public/CDN URLs for any files intended for public use.

## Access, database account, and operations

The API is disabled by default. Set `CATALOG_PUBLIC_API_ENABLED=true` only after the separate read account is provisioned. The API returns 503 `API_UNAVAILABLE` while this toggle is false or the Catalog module is disabled, even if response-cache entries exist.

Set both `CATALOG_PUBLIC_API_DB_USERNAME` and `CATALOG_PUBLIC_API_DB_PASSWORD` in deployment secrets. The account must be distinct from the application's catalog backend account and must connect to the same existing catalog database. It must have only `USAGE` and `SELECT` grants, with no grant option or additional privilege; each request checks grants and sets the session transaction read-only. Example provisioning with sanitized placeholders:

```sql
CREATE USER 'catalog_public_api'@'<application-host>' IDENTIFIED BY '<strong-secret-from-secret-manager>';
GRANT SELECT ON `<catalog-database>`.* TO 'catalog_public_api'@'<application-host>';
```

The placeholders must be replaced with deployment-specific values. The application derives the public connection's host, port, database, and charset from the existing catalog connection, including parsed database URLs. Existing PDO TLS/CA options are preserved. Native prepared statements and unbuffered reads are enforced on the new connection. Missing credentials, an account shared with the backend, or excessive grants fail closed; connection/server failures receive generic internal errors.

Per IP, the default rate limits are 60 requests/minute shared by all routes, plus 20/minute for search or 30/minute for parts/facets. The limits use Laravel's configured rate-limiter cache (Redis when configured as the limiter store); no `X-Forwarded-For` value is parsed manually. Do not change proxy trust settings for this API alone. If deployed behind a proxy, configure Laravel to trust only the known proxy addresses so `$request->ip()` identifies the client correctly.

Server-side caching is limited to root, tree, category, and resolve payloads, for 300 seconds by default. It uses 512 bounded cache slots; an individual cached payload is limited to 1 MiB. Slot collisions cause a cache miss, never a different resource response. Hierarchy and part counts may remain stale until TTL expires. Other endpoints remain live, including fields, metadata, parts, facets, search, and health, so field visibility revocation is immediate. API/module disablement is checked on every request, including cached routes and long-running workers. Configuration changes require the normal Laravel config-cache rebuild and worker reload.

Configurable resource bounds include 10,000 hierarchy nodes, actual depth 64, 200 public fields, 1,000 facet values per field, 8 KiB query strings, and 8 MiB JSON responses. Database rows are read with unbuffered cursors under a cumulative per-request byte budget; expanded part defaults and hierarchy paths also consume a budget. A request can reach the conservative read budget before the final JSON limit. Resource-limit violations return 503 `RESOURCE_LIMIT`; cycles or invalid hierarchy/depth return 500 `INVALID_HIERARCHY`. Data is never silently truncated except for the documented 100-result part-search cap.

## WordPress integration

Call the API from server-side PHP using `wp_remote_get()` with a 5-second timeout. Check `is_wp_error()` before reading the response, validate the HTTP status and JSON envelope, and use a WordPress transient for a short fresh value plus a stale fallback if the API is temporarily unavailable. Keep the API URL and any integration secrets server-side. Escape text with `esc_html()` and approved media URLs with `esc_url()` at output time. Require HTTPS for the API base URL and do not enable browser CORS or expose catalog credentials in JavaScript. This document describes an integration pattern; no WordPress plugin or deployment is included.

```php
function electronics_catalog_get(string $route, array $query = []): ?array
{
    $base = 'https://catalog.example.com/api/v1/catalog'; // Set the deployed HTTPS URL.
    $url = add_query_arg($query, $base.'/'.ltrim($route, '/'));
    $key = 'eh_catalog_'.hash('sha256', $url);
    $fresh = get_transient($key.'_fresh');
    if (is_array($fresh)) {
        return $fresh;
    }
    $response = wp_remote_get($url, [
        'timeout' => 5, 'redirection' => 0, 'sslverify' => true,
        'headers' => ['Accept' => 'application/json'],
        'limit_response_size' => 8388608,
    ]);
    $payload = ! is_wp_error($response) && wp_remote_retrieve_response_code($response) === 200
        ? json_decode(wp_remote_retrieve_body($response), true) : null;
    if (is_array($payload) && ($payload['success'] ?? false) === true && is_array($payload['data'] ?? null)) {
        set_transient($key.'_fresh', $payload['data'], 60);
        set_transient($key.'_stale', $payload['data'], 5 * MINUTE_IN_SECONDS);
        return $payload['data'];
    }
    $stale = get_transient($key.'_stale');
    return is_array($stale) ? $stale : null;
}

$tree = electronics_catalog_get('tree');
$seriesPath = implode('/', array_map('rawurlencode', explode('/', 'electronics/passives/r-series')));
$parts = electronics_catalog_get('series/'.$seriesPath.'/parts', [
    'filter' => ['voltage' => ['12', '24']], 'page' => 1, 'per_page' => 25,
]);
foreach ($parts['parts'] ?? [] as $part) {
    echo '<p>'.esc_html($part['sku']).' '.esc_html($part['description'] ?? '').'</p>';
}
```

Build navigation from `tree[].children` and `resource.path`, then retrieve `series/{path}` for specifications and `series/{path}/facets` for filter options. Use `pagination.last_page` for further part pages and `search?q=...` for catalog search. Render non-null approved file values with `esc_url()`; render names, descriptions, labels, and values with `esc_html()`. A 404 means the resource is missing; a 422 means the request needs correcting; for 429 respect `Retry-After` before a later request. For 500/503 or a timeout, serve the short stale fallback or a temporary-unavailable message. Never cache an error as successful data. Purge WordPress transients when revoking public content if immediate removal is required. Any future optional server-to-server authentication should remain an independent integration layer; V1 requires no token.

The example uses the supported [WordPress HTTP API](https://developer.wordpress.org/reference/functions/wp_remote_get/) and [Transients API](https://developer.wordpress.org/apis/transients/). It is a copyable integration example, not an installed WordPress change.

## Compatibility changes from the source API

The data keys and nesting are preserved except for the explicitly documented health `database` omission and the versioned endpoint paths. The integration intentionally tightens several behaviors:

- Paths are decoded exactly once and reject malformed/double encoding, traversal, separators, and control characters. There is no `?route=` override.
- Unknown or malformed query parameters, invalid page values, and `per_page` above 100 are rejected with 422 instead of being ignored or clamped. A valid page beyond the final page is still clamped.
- Text sort uses database lexical order (so `R10` sorts before `R2`); `number` fields sort numerically. This gives stable database pagination instead of sorting all rows in PHP with natural ordering.
- `%` and `_` in searches are literal. Part-list search examines approved public product columns and public non-file values; global search examines part columns and node names. Neither searches hidden values or field keys.
- Slug collision suffixing handles collisions with naturally suffixed sibling names. Hierarchy cycles, broken parent links, or excessive depth return a bounded hierarchy error.
- Public visibility is denied when either public hide flag is set. File values must be approved HTTPS URLs and are never returned as private relative paths.
- The API uses the existing database without new migrations, but requires a separate least-privilege read account and read-only database session.
